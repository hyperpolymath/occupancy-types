== This repository: occupancy-types

Stepwise resource-bounding types: deterministic memory first, network
resources second. This checkout hosts the *Session IR calculus, checker and
Idris spike* (ULTRAPLAN R0-B) and the *stackcert* certificate checker (R1)
on top of the RSR scaffold.

== Type-family map (estate coherence)

This repo is one node of the hyperpolymath type-theory family. The shared
map — vocabulary, connection obligations, ownership routing — lives in
https://github.com/hyperpolymath/nextgen-typing[`nextgen-typing`]:
link:https://github.com/hyperpolymath/nextgen-typing/blob/main/docs/TYPE-CONNECTIONS.adoc[TYPE-CONNECTIONS.adoc].

* *Question this repo asks* — how do live-state footprints compose, and when
  are they reclaimed? (Occupancy/HWM grades; protocol frontier = reclamation.)
* *Boundary* — an occupancy bound is not a cost bound (HWM monoid ≠ max-plus);
  a measured live-byte count is not an occupancy grade. Cost grades live in
  link:https://github.com/hyperpolymath/tropical-types[tropical-types]
  (the ULTRAPLAN name `tropical-resource-typing` resolves there).
* *Not this repo* — echo indices, warrants, residue measures (shared glossary
  in TYPE-CONNECTIONS separates all of these from resource grades).

== Quick start

[source,bash]
----
# 1. Create a repo from this template (or clone it), then from the repo root:
mise trust                    # allow this repository's mise.toml (needed without a TTY)
mise install                  # the toolchain, including the yq repo-init needs
mise exec -- just repo-init   # interactive bootstrap: fills every {{PLACEHOLDER}}

# 2. See the available tasks:
mise exec -- just             # lists all phases (build, test, validate, audit, ...)

# 3. Check the repo still satisfies the RSR shape:
mise exec -- just validate    # structure + metadata checks
----

`mise exec --` puts the toolchain on `PATH` for that one command. Once mise is
activated in your shell (`eval "$(mise activate bash)"`, or your shell's
equivalent), plain `just` works and the prefix can be dropped.

`just repo-init` prompts for the project name, owner, author, licence contact, and the
other values listed in `.machine_readable/ai/PLACEHOLDERS.adoc`, substitutes them
across the tree, validates the result, and (if available) runs the `k9-svc` checks.

=== Minting without a terminal

Agents and CI can mint non-interactively: set `RSR_NON_INTERACTIVE=1` and pass
the answers as environment variables named like the prompts' variables in
`build/just/repo-init.just` (`PROJECT_NAME`, `REPO`, `OWNER`, `AUTHOR` and
`AUTHOR_EMAIL` are required; any other answer left unset is blank or takes its
default). Piping the answers to stdin in prompt order also works.

== Governance badges

The *K9 conformance* badge in the row at the top becomes live after
`just repo-init` replaces the `hyperpolymath` and `occupancy-types` placeholders in its URL
and an eligible push to `main` publishes it. It is published by
`.github/workflows/dogfood-gate.yml` to a generated *orphan* branch called
`governance-badges`, and read back through the shields endpoint.

[cols="1,3",options="header"]
|===
| Badge | What it means

| green `success`
| The K9 lane ran for that commit on `main` and passed.

| red `failure`
| The K9 lane ran for that commit on `main` and failed.

| grey `skipped`, `cancelled`, `unavailable`, `unknown`
| That commit produced *no trustworthy* K9 result. Grey is not "pending" and
  not a stale green: a skipped, cancelled or unavailable lane replaces an
  earlier green badge with grey.
|===

* `governance-badges` is *generated output*. It deliberately has *no common
  ancestor with `main`*, it has no pull request, and it must *never be merged*.
  Recent pushes to it are ordinary badge refreshes.
* A run that would publish the same bytes makes *no commit at all*.
* Nothing in the badge pipeline can turn a failing validation green: only a
  lane that ran and passed, with its artifact present, renders brightgreen.

The full operational contract - the exact state table, how API errors are
classified, how concurrent publications are serialised, and how to repair a bad
file - is in link:.github/workflows/README.adoc[`.github/workflows/README.adoc`].
